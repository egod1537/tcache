## Existing interface risks and ownership handoff

Code audit reconfirms `RouteProviderResult.result: unknown`, provider-local Kakao route types, a closed provider-name union without TMAP/Naver, and KR defaults of Kakao Mobility driving / Kakao Maps walking. Cache keys are provider-scoped `route:v4`; these technical namespaces confer no data usage rights.

The resolver rejects departure time only when capability explicitly equals false. Kakao Mobility leaves it undefined while its mapper omits departure time, so a future request can be accepted without affecting the upstream request. Mobility parsing also treats absent result_code as potentially successful; parsers can return null totals/empty paths. The existing synthetic PASS therefore does not prove strict schema validation. Provider raw responses enter debug handling; retention/exposure must be audited before any permitted production rollout.
